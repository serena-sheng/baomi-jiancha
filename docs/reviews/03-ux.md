# 03 · 交互流程评审

**结论**：扫描时列表在指针下重排，「脱密」一击生效且无法撤回。先修这两处。

**旅程**：菜单栏盾（数字含义不明）→ 清单（计数像筛选却不可点；只显示前 800 条 `Store.swift:150`）→ 扫描中每 40 个文件刷新并按等级重排（`main.swift:196`、`id:\.offset` :365）→ 读命中（无位置/值，未说「提示≠定密」）→ 点行打开访达而非勾选（`scanning.png`）→ 点「脱密」即执行（原件进隐藏目录，格式可能改）→ 成功后行消失 → 回收目录平铺只剩文件名；重启后痕迹全无。

**必答**
1. 会误点：行按等级/时间重排，新命中把行下推，行尾「脱密」可能落到另一份；选中按路径存储尚不出错，但掉出 800 条后仍计入底部。
2. 原件进 `Application Support/保密检查/trash`（非废纸篓），平铺、同名加时间戳（`Engine.swift:1655`）；副本回原位，.doc→.docx；无撤销，只能手动搬回且不知回哪。
3. 失败仅在本次会话可见，状态还替换掉该行「脱密」按钮，无法就地重试；结束即清空选择。
4. 选中不必持久；处理结果（失败原因、原件↔副本）必须持久，现在全在内存。

**六条改进**
1. 冻结列表。扫描中不重排，新命中写顶部 `扫描中 · 12 条新命中，扫描结束后一起显示`；`id` 改路径；行点击=勾选，访达降为行尾次级操作。
2. 计数当筛选，全选限当前筛选。37,132 条提示只列 800 却写「全选」，可一键把 800 份送进脱密。文案 `全选（当前筛选 12 个）`、`已选 12 个 · 筛选外还有 36,320 条`。
3. 脱密后留行可撤销：`已脱密 · 原件在回收目录 · 撤销`；撤销=原件移回、删副本；回收目录按原路径分层；结果补 `遮盖 2 处、删除密级标志行`。
4. 批量先看清单、可中止：底栏 `正在处理 12/800` +「中止」，剩余保持勾选；确认语 `将处理 12 个文件，原件移入回收目录，可撤销`。
5. 失败可找回：结果落库、文件变更即失效；头部加失败筛选；失败行常驻 `重试`；完成在窗内摘要 `2 个没处理成功，原件没动 · 查看`。
6. 三态分开：枚举期 `正在清点文件，先不显示进度`（现为 0/0）；空态 `还没扫过：首次扫描会读很多文件，请让它跑完` / `扫描中，命中会实时出现在这里` / `已扫描 25,560 个文件，没有需要处理的内容`；权限横幅加 `已授权？重新检查一遍` 与 `仍读不到就退出并重开应用`。
